# Проверка исправления CI — 8 октября 2026

Ветка `fix-ci` создана от актуальной версии `release/product` (`f6cb5ba`).
Рабочая база и контейнеры приложения при проверке не изменялись: использован
отдельный PostgreSQL с образом `pgvector/pgvector:0.8.6-pg17-bookworm`.

## Воспроизведённая ошибка

Job `schema-equivalence` обнаруживала расхождение между чистой установкой и
обновлением от `d5cde74`:

- базовая схема создавала UNIQUE constraint
  `assistant_kb_documents_path_content_sha256_version_key`;
- миграция `0076` создавала уникальный индекс
  `assistant_kb_document_chunker_version` по тем же трём колонкам.

Оба варианта обеспечивали уникальность, поэтому работа приложения сама по себе
не выявляла расхождение. Проверка эквивалентности правильно обнаруживала разные
объекты схемы.

## Исправление

- Базовая схема создаёт канонический уникальный индекс, совпадающий с миграциями.
- Новая миграция `0077_assistant_kb_document_uniqueness` нормализует уже
  установленные базы: сначала создаёт канонический индекс, затем снимает
  дублирующий UNIQUE constraint. Старые применённые миграции не изменялись.
- Отметки миграций для чистой установки обновлены генератором.
- Jobs `unit` и `pg` публикуют JUnit-отчёты в GitLab, включая неуспешные запуски.
- E2E переходит на экран загрузки перед проверкой баннера viewer: стартовой
  страницей стала сводка. Проверяется отсутствие обеих операций загрузки,
  а не только одной из них.
- Проверки и их критерии не отключались и не ослаблялись.

Браузерный сценарий выполнен в образе `mcr.microsoft.com/playwright:v1.63.0-noble`
с пакетом playwright-core той же версии, реальным сервером приложения и отдельной

Для PostgreSQL-проверок использовались только отдельные тестовые базы. Для
проверки обновления старая схема извлекалась через `git archive d5cde74 db build`;
сравнивались полные результаты `tools/schema_fingerprint.py`, без исключения
ограничений или индексов из сравнения.

На предоставленном скриншоте показан pipeline ветки `main`. После обновления
удалённых ссылок подтверждено, что `main` (`bb868fa`) содержит ту же версию
файлов, что и исходная `release/product` (`f6cb5ba`). Все восемь красных jobs
не означают восемь воспроизведённых ошибок кода: локально подтверждены
расхождение схем и устаревший переход в E2E. Для остальных сбоев необходим
текстовый лог runner. API удалённого CI не предоставил доступ к логам, поэтому
локальные результаты не выдаются за статус удалённого pipeline.
