# UI_DESIGN — оформление интерфейса

Решение принято: основа — **«Маршрутный лист»**, тёмная **«Звёздная карта»** —
только на экране звёздной карты. Этот документ фиксирует палитру, шрифты,
раскладку и правила, чтобы их не пришлось выбирать заново.

Что показывать и откуда брать данные — `docs/UI_SPEC.md`. Здесь только то, как
это выглядит.

Стек: React 19 + Vite + TypeScript, **Mantine** для таблиц, вкладок, загрузки
файлов и боковых панелей. Гант — CSS grid, звёздная карта — своё SVG.
Сторонних чартов нет.

---

## 1. Идея

Квартал — почтовый маршрут: шесть спринтов, шесть пунктов, задача идёт по ним с
трек-статусом. Идентификаторы задач (`ONK-2475`, `DB-202`) и правда читаются как
трек-номера, поэтому моноширинный шрифт для них — смысл, а не украшение.

Пользователь — руководитель разработки и ресурсный менеджер. Его вопрос не
«красиво ли», а «что не влезло и почему». Поэтому объяснение решения — не
подпись мелким шрифтом, а полноправный элемент экрана.

**Смелость в одном месте:** шесть колонок спринтов — несущая спина интерфейса.
Одна и та же сетка на плане, на рисках и на графике выполнения спринтов, чтобы
взгляд переносился между экранами без перенастройки. Всё остальное тихое.

## 2. Палитра

Светлая тема — везде, кроме звёздной карты.

| Токен | Hex | Где |
|---|---|---|
| `--ink` | `#14213D` | текст, заголовки, линии спины |
| `--paper` | `#EDF0F3` | фон страницы |
| `--surface` | `#FFFFFF` | таблицы, панели, полосы задач |
| `--line` | `#D5DBE2` | границы, сетка |
| `--muted` | `#5A6472` | служебный текст, подписи |
| `--stamp` | `#C1121F` | срыв квартала, ошибка |
| `--wax` | `#E3B23C` | сдвиг, предупреждение |
| `--route` | `#2A9D8F` | выполнено, в норме |

**Контраст измерен, не на глаз** (отношение к `--paper`):
`--ink` 13.96 · `--muted` 5.24 · `--stamp` 5.44 · `--route-text` 5.01 ·
`--wax-text` 4.79 — все проходят AA для основного текста.

А вот `--wax` (1.72) и `--route` (2.91) для текста **непригодны** — только
заливки, линии и точки. Для текста тех же смыслов брать тёмные пары:
`--wax-text #8A6212`, `--route-text #1E7268`.

Тёмная палитра — **только звёздная карта**:

| Токен | Hex | Где |
|---|---|---|
| `--void` | `#0B1020` | фон карты |
| `--field` | `#141B2E` | панели поверх карты |
| `--star` | `#E8ECF5` | текст, ядра команд |
| `--orbit` | `#7FA6D9` | орбиты, связи |
| `--flare` | `#FF6B5A` | критический риск |
| `--ember` | `#FFC857` | единственный носитель |
| `--bloom` | `#6CCFA6` | в порядке |

Контраст к `--void`: `--star` 16.0 · `--ember` 12.3 · `--bloom` 10.0 ·
`--orbit` 7.5 · `--flare` 6.8 — на тёмном запас есть у всех.

## 3. Типографика

**Одно семейство на весь продукт: Golos Text** (Google Fonts, кириллица
родная — гротеск Paratype, сделанный для государственных сервисов). Второе —
**PT Mono**, и только для идентификаторов задач, инженеров и числовых колонок,
где важно выравнивание.

Третьего семейства на звёздной карте **нет**: там меняется палитра, а не шрифт.
Один стиль набора на все экраны держит продукт цельным.

```
38 / 1.15  -0.01em  600   заголовок экрана
28 / 1.2   -0.01em  600   крупное число в штемпеле KPI
22 / 1.3            500   заголовок блока
18 / 1.4            500   имя задачи, инициативы
15 / 1.5            400   основной текст, причины решений
13 / 1.45           400   служебный текст, подписи к осям
13 / 1.4            400   PT Mono: task_id, engineer_id, часы, SP
```

Длина строки текста причин — до 80 знаков. Числа в таблицах — `font-variant-numeric: tabular-nums`.

## 4. Приёмы, которые несут смысл

| Приём | Что кодирует |
|---|---|
| Шесть колонок спринтов | сетка квартала; одна и та же на трёх экранах |
| Вертикальная линейка слева у строки | уровень риска: `--stamp` / `--wax` / `--route` |
| Круглый штемпель | KPI: **тонкое кольцо — прогноз, залитая дуга — факт**. Требование ТЗ «отличать прогноз от факта» показано формой, а не подписью |
| Деления внутри полосы задачи | доли Story Points по спринтам (`plan_task_sp`): «8 SP при ёмкости 7.2» перестаёт выглядеть ошибкой |
| Штриховка сегмента назначения | заём инженера у другой команды (`is_loan`) |
| Номера спринтов | это последовательность, нумерация здесь — содержание |

## 5. Экраны

Порядок сборки — сверху вниз.

### 5.1. Загрузка

Первый экран, потому что без него жюри нечего нажимать.

```
┌───────────────────────────────────────────────────────────┐
│ Загрузка данных                                           │
│                                                           │
│  ┌── Датасет ────────────┐  ┌── Факт спринта ───────────┐ │
│  │ перетащите .xlsx      │  │ следующий: спринт 4        │ │
│  │ [ Загрузить датасет ] │  │ [ Скачать шаблон ]         │ │
│  │                       │  │ перетащите .csv / .xlsx    │ │
│  │ Загрузка начнёт новый │  │ [ Загрузить факт спринта 4]│ │
│  │ цикл: прогоны и факт  │  └────────────────────────────┘ │
│  │ будут стёрты.         │                                 │
│  └───────────────────────┘                                 │
│                                                           │
│  История загрузок                                         │
│  ▸ спринт 3 · 22.09 19:14 · 4 задачи · план пересчитан    │
└───────────────────────────────────────────────────────────┘
```

Ответ `400` несёт `problems` — список проблем по строкам. Показывать **целиком**,
списком, без сворачивания: это главный способ понять, что не так с файлом.

### 5.2. План квартала

```
┌────────────────────────────────────────────────────────────────┐
│ План квартала   PI-2026-Q3 · 01.07—22.09 · прогон 4 · факт сп.3│
├──────────┬───────┬───────┬───────┬───────┬───────┬───────┬─────┤
│ инициатива│   1   │   2   │   3   │   4   │   5   │   6   │     │
│ PRODF-7124│ ▐███████▌▐██▌                                │ ⓘ   │
│  ●90      │ DB-202                                       │     │
│ PRODF-7120│ ────────────  KP-3898                        │ ⚑   │
└──────────┴───────┴───────┴───────┴───────┴───────┴───────┴─────┘
```

Полоса — задача, деления внутри — доли SP. Пунктир — не в квартале. Клик по
строке открывает боковую панель Mantine с `reason_text` как есть и разбором из
`reason_details`: кто закрывает роли, займы, растяжка SP.

Базовая линия Недели 0 — отдельным запросом с `run_id` канонического прогона,
рисовать тонким контуром под текущей полосой.

### 5.3. Риски

Лента, сгруппированная по спринтам той же сеткой. У каждой строки слева линейка
уровня. Под алертом — строка из `v_plan_diff`: `cause` и `explanation`
(«не закрыта к концу спринта 1 — остаток переносится дальше»).

Отдельным блоком — предупреждения приёмки `v_plan_violations`. Пусто — зелёная
строка «Предупреждений нет», а не пустое место.

### 5.4. Звёздная карта — тёмная

Шесть ядер-команд по окружности, инженеры — спутники вокруг своего ядра.
Четверо парттаймеров на общей орбите между двумя ядрами: их связь тянется к
обоим. Радиус спутника — грейд, цвет — риск из `v_bus_factor_skill`.

Раскладка **детерминированная**, не силовая: ядра по кругу, спутники равномерно
по своей дуге. Силовая раскладка «плавает» между перерисовками, и карту нельзя
показать дважды одинаково.

Боковая панель по клику — `v_engineer_absence_risk`: компетенции, где человек
единственный носитель, и задачи текущего плана, которые встанут без него.

Покрытие ролей (роли, которых нет в штате) — **отдельный блок**, а не те же
точки: это найм, а не незаменимость.

### 5.5. KPI

Два штемпеля: процент выполнения квартала и выполнение плана спринта. Кольцо —
прогноз, дуга — факт. Норму брать из `target_min` / `target_max` строки, во
фронте не зашивать. Ниже — шесть делений спринтов с фактом и прогнозом.

### 5.6. Роли и ёмкость · 5.7. Профили

Таблицы Mantine. `gap_hh` приходит строкой — знак читать как текст, а не через
`parseFloat`. Блок диагностики (`v_dq_summary`) — здесь же.

## 6. Чего не делать

Список конкретный, потому что каждый пункт — типовой признак сгенерированного
интерфейса:

- **набранные капслоком подписи** над заголовками;
- **стрелка `→` в тексте кнопок**;
- строки-метаданные, склеенные точками по центру (`A · B · C`);
- **одинаковые карточки** с одним радиусом и одной серой тенью под всем подряд;
- градиентные заливки как украшение;
- появление блоков с затуханием и сдвигом при каждой прокрутке; анимация — только
  в ответ на действие (открылась панель, принят файл);
- дефолтный вид Mantine: синий `primaryColor`, радиус `sm` везде, `Paper` с тенью
  вокруг каждого блока.

## 7. Тема Mantine

```ts
import { createTheme, rem } from '@mantine/core'

export const theme = createTheme({
  primaryColor: 'post',
  primaryShade: { light: 8, dark: 6 },
  defaultRadius: 2,          // маршрутный лист, а не карточки
  fontFamily: "'Golos Text', system-ui, sans-serif",
  fontFamilyMonospace: "'PT Mono', ui-monospace, monospace",
  headings: {
    fontFamily: "'Golos Text', system-ui, sans-serif",
    sizes: {
      h1: { fontSize: rem(38), lineHeight: '1.15', fontWeight: '600' },
      h2: { fontSize: rem(22), lineHeight: '1.3', fontWeight: '500' },
      h3: { fontSize: rem(18), lineHeight: '1.4', fontWeight: '500' },
    },
  },
  colors: {
    post: ['#EEF1F6','#D8DFEA','#B4C1D6','#8DA0C0','#6E85AD',
           '#5A73A1','#4E6899','#3F5885','#14213D','#0D1729'],
  },
})
```

Семантические цвета — CSS-переменными на `:root`, а не через Mantine: их читает и
SVG звёздной карты, которому палитра Mantine недоступна.

## 8. Тексты

Кнопка называет действие и сохраняет имя до конца: «Загрузить факт спринта 4» →
уведомление «Факт спринта 4 загружен, план пересчитан». Не «Отправить».

Пустые экраны направляют, а не извиняются: «Датасет не загружен. Загрузите
выданный .xlsx — план построится автоматически». Ошибки говорят, что произошло и
что сделать, без «к сожалению».

`reason_text` из базы уже написан по-русски и готов к показу — не пересказывать
его во фронте и не сокращать.

## 9. Планка качества

- работает от 360 px: спина квартала на узком экране прокручивается
  горизонтально, подписи инициатив липнут слева;
- фокус с клавиатуры виден на всех интерактивных элементах;
- `prefers-reduced-motion` уважается;
- цвет никогда не единственный носитель смысла: рядом с линейкой риска — слово
  («срыв», «сдвиг», «в норме»);
- `numeric` из API приходит строкой, `null` рисуется как «—», а не как 0.
